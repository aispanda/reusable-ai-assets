# Issue-resolution patterns

Record only failures that improve this reusable workflow. Keep raw logs out; retain the smallest evidence needed to reproduce and prevent recurrence.

| ID | Trigger / symptom | Root cause and evidence | Safe resolution | Preventive improvement | Verification | Status |
|---|---|---|---|---|---|---|
| AR-001 | `scaffold_asset.py` raised `PermissionError` when creating an asset in the central library | The central library was outside the active project's normal write boundary; the failure occurred before an asset folder or inventory row was created | Confirm the exact central target, then rerun only the scaffold command with scoped write authorization | Scaffold now returns a concise permission instruction and rolls back a newly created folder if a later write fails; workflow requires scoped approval for external canonical libraries | RA-004 scaffold succeeded with scoped authorization; smoke test, skill validation and central library validation passed | Resolved 2026-08-06 |
| AR-002 | Standard skill validation failed first with missing `yaml`, then with a Windows character-decoding error | The bundled Python lacked PyYAML; system Python had it but defaulted to a non-UTF-8 locale while the skill used valid Unicode punctuation | Use an environment containing the validator dependency and enable Python UTF-8 mode for that command | Validation instructions should declare the PyYAML dependency and use UTF-8 explicitly on Windows; asset scripts themselves remain standard-library-only | `PYTHONUTF8=1` with system Python returned `Skill is valid!` for RA-005 | Resolved 2026-08-06 |
| AR-003 | Running an asset’s audit tests left `scripts/__pycache__` inside the canonical transferable package | The audit imported a sibling module with normal bytecode caching enabled; the package manifest exposed the generated `.pyc` after validation | Remove the exact generated cache and disable bytecode writes before local helper imports | Reusable Python validation tools that import sibling scripts should set `sys.dont_write_bytecode = True` or run with `PYTHONDONTWRITEBYTECODE=1`; always inspect the final transfer manifest after tests | RA-005 tests passed after the change and a final recursive file check found no cache artifact | Resolved 2026-08-06 |

| AR-004 | A new-asset scaffold reported that the requested ID was already registered | The capability already existed under an established asset name; creating another folder would split ownership and make inventory discovery ambiguous | Stop scaffolding, read the existing `ASSET.md` and entry skill, then enhance that asset in place while preserving its stable ID and boundary | Before assigning an ID or folder, search the central inventory by capability, keywords and adjacent assets; prefer versioned enhancement over a competing asset | RA-006 retained its stable identity and received website-strategy, ecosystem and profile-governance additions without a duplicate inventory row | Resolved 2026-08-06 |
| AR-005 | A library marked reusable still contained another project's names, configuration, schema fixture and machine paths | Structural validation checked manifests but not public content boundaries; several examples were copied from working projects | Replace project material with fictional profiles, parameterize machine paths and quarantine private evidence outside the transferable package | Public validation now supports strict machine-path, secret-pattern and repeatable forbidden-term checks; require it on a staged package before publication | Contamination fixture fails the enhanced validator; clean staged library must pass before push | Resolved 2026-08-06 |
| AR-006 | An AI utility loaded credentials from one hard-coded personal `.env` location | Convenience configuration crossed the reusable-core boundary and made the asset machine-specific | Read standard environment variables or an ignored project-local `.env`; production consumers use an approved secret manager | Strict validation rejects personal machine paths and credential-like content; quality gate requires replaceable configuration | Utility source and usage guidance generalized; staged public scan required | Resolved 2026-08-06 |
| AR-007 | A central library contained dependency folders, generated builds and Python bytecode beside reusable source | Local execution output was not separated from the transfer package | Ignore all generated/dependency paths and construct publication from a clean staged copy | Root ignore policy plus strict validator reject dependency, generated and bytecode paths | Staged file manifest and strict validation required before public commit | Resolved 2026-08-06 |
| AR-008 | Validation could not start because `python` was not on the operator's `PATH` | Documentation assumed a global runtime instead of resolving the approved project/workspace runtime | Resolve a configured Python executable during preflight; do not install or hard-code one machine's runtime into the asset | Publication workflow records the runtime/version used, while examples use a configurable `python` placeholder | Smoke test passed with the approved workspace runtime | Resolved 2026-08-06 |
| AR-009 | Publication checks depended on repeatedly typing private project terms and local exceptions | The reusable validator had secure generic defaults but no persistent project-owned policy contract | Add a JSON `--policy` interface for forbidden terms, extra secret/path patterns, credential filenames and generated folders; keep one-off CLI overrides | Asset code contains no client-specific rules; each consumer owns its policy file and can version a sanitized policy or keep a private one outside the public package | Clean and contaminated policy-driven fixtures pass/fail as expected | Resolved 2026-08-06 |
| AR-010 | The generic skill-creator checker could not run in the selected bundled runtime | That checker imports PyYAML, which was absent; installing packages merely for validation would add environment drift | Run the asset's dependency-free smoke tests and direct frontmatter/line-limit checks; use the generic checker only from an approved runtime that already supplies its dependencies | Validators must declare or avoid runtime dependencies; never hard-code a personal interpreter path into the asset | Policy smoke test and direct skill-structure validation passed | Resolved 2026-08-06 |
| AR-011 | A Bash-based asset test failed from PowerShell because the located shell lacked Unix utilities on its non-login path | Finding an executable did not prove that its expected runtime environment was initialized | Invoke the approved shell as a login environment, or ask the operator to run the command from that shell's own terminal; never install a replacement implicitly | Runtime preflight verifies one representative utility as well as the shell version before running the suite | Deployment test passed through Git Bash login mode | Resolved 2026-08-06 |
| AR-012 | A validated public package failed its commit gate on trailing spaces and repeated blank lines at end-of-file | Content and portability checks did not include repository whitespace rules | Normalize publishable text mechanically before staging; preserve content and rerun functional tests afterward | Publication workflow includes `git diff --cached --check` after staging and before commit | Canonical and staged text normalized; commit gate rerun | Resolved 2026-08-06 |
| AR-013 | A clean approved commit could not be pushed because Git used cached credentials for an unrelated account | Commit author configuration was verified, but the independent remote-authentication principal was not | Before committing, compare the target repository owner with the active Git credential account and confirm write access; switch accounts through the approved credential manager when mismatched | Public-source gate records remote URL, visibility, commit author and authenticated principal separately | Push failed safely with HTTP 403 before publication | Resolved 2026-08-06 |

When the same root cause recurs, update the existing row and prevention rather than adding a duplicate issue.
