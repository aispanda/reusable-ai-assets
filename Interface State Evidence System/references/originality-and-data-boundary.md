# Originality and data boundary

## Purpose

This asset supports independent problem solving. It may learn from general interaction patterns, but it must not reproduce another party’s expressive work or import private information into reusable materials.

## Use general patterns, not copied expression

A functional need such as “show progress, provide a safe retry, separate restricted actions, or make feedback traceable” can be independently defined. The visible expression of that need must be created from the consuming project’s own requirements, language, components, tokens, and evidence.

| Safe practice | Do not do |
|---|---|
| Describe the user need and acceptance evidence in original neutral language | Copy another product’s feature names, marketing language, help text, or internal terminology |
| Create fresh fixtures and examples | Reuse visible conversations, posts, member records, screenshots, or other personal content |
| Use independently chosen component structure and visual roles | Replicate a distinctive layout, visual hierarchy, artwork, brand expression, or interaction sequence without an independent rationale |
| Keep reference provenance in an internal research note when needed | Cite or imply a partnership, endorsement, association, or origin that does not exist |
| Record license and source for code, icons, fonts, images, and data | Assume public availability equals permission to copy or redistribute |

## Fixture rules

Fixtures are synthetic, stable, and minimal. They should reveal the state contract without exposing identities, credentials, direct contact details, private context, production identifiers, or sensitive inferences. A restricted fixture demonstrates the boundary through a generic capability state and a safe explanation; it does not disclose what the restricted person cannot access.

## Data minimization rule

Collect, display, and retain only the information required for the declared outcome. Before adding data collection, profiling, or measurement, document purpose, visibility, access, retention, deletion, and review. Aggregate, purpose-limited signals are preferred to unnecessary individual behavioral tracking.

## Review triggers

Seek qualified review before release when the work involves a consequential intellectual-property question, personal or sensitive information, a material consumer claim, contractual commitment, regulated context, child or safeguarding concern, accessibility conformance assertion, jurisdiction-specific requirement, or a dispute about source rights.

## Documentation rule

Record the requirement, approved decision, fixture boundary, evidence, and known limitation. Do not record the identity or confidential strategic intent of a reference source in a reusable asset or public-facing implementation record.
